# 字形 PNG 底稿（绘制 / 校对 / 手工改字）

**每个字只有一张图**，用字本身命名；中文版新追加的字形在文件名末尾加 `（新）`。

| 文件名 | 含义 |
|---|---|
| `{字}.png` | 该字的**正式字形槽**（编码器实际写入的最低下标槽），改字就改这个 |
| `{字}（新）.png` | 同上，但属于中文版**新追加**的字形（下标 ≥ 0x6A8，日文原版没有） |
| `重复_{下标}.png` | 另一个存放同一个字的槽位；你在正式文件上的改动会**同步写进这些槽** |
| `未使用_{下标}.png` | 没有分配文字的槽位（空图或残余图案） |

* 尺寸：128×128（= 16×16 的 8 倍，最近邻放大，**一个方块 = 一个像素**）
* 颜色：游戏**原生文字调色板**，所见即所得
  * 背景 `(248,248,248)` = 透明（像素值 0）
  * `(80,80,80)` = **字身**（像素值 1）
  * `(104,96,88)` = **右侧 1px 投影**（像素值 2）
* `manifest.tsv`：`file / index / code / char / is_new / role / ink` 对照表
  （`role` = `canon` / `dup` / `unused`；`ink` = 墨量像素数）
* 文件名由导出脚本维护，**不用自己改名**；目录里过期的 PNG 会被自动删除，
  所以目录内容永远与当前 ROM 一致。

## 原版字形的规格（实测自日文原版 ROM）

| 项 | 值 |
|---|---|
| 用色 | **只有 1、2 两级**（1703 个字形全部如此） |
| 字身 | **11×11 设计框**，位于单元格 `(0,1)`；中位尺寸 11×11，最大 12×12 |
| 投影 | **字身右侧 1px**（`值2`），自动生成；y 方向不投影 |
| 墨量 | 字身平均 **50.5 像素/字**；字身:投影 ≈ **65:35** |
| 单元格 | 16×16，右侧/下侧留白（所以字不会顶到边） |

> 早期版本用系统字体渲染成 1–15 全灰阶并填满 16×16，
> 结果实心笔画落在**接近白色**的调色板索引上（索引 15 ≈ 232），
> 于是又细又淡、大小也不对。现已按上表量化重做，与原版一致。

## 手工改字后怎么打回 ROM

```bash
python3 tools/build_rom.py --out out.gba      # 打包时自动套用目录里的手改字形（含自检）
```

打包流程会打印 `[phase] applying hand-edited glyphs` 并报出真正改动的字数，
所以**重新打包不会丢掉手改的字形**。

只想把改字单独写进现成 ROM（不重新打包）时：

```bash
python3 tools/import_glyphs.py --rom out.gba --out out.gba --autoshadow
```

* 改好 PNG（保持 128×128，或任意尺寸会自动归一）即可；**一个字只需改一张图**，
  该字占用的其它槽位（`重复_*`）会自动同步成同一张图。
* `--autoshadow` 按原版规则由字身自动补出右侧投影；只想改新字可加 `--only-new`。
* `--dry-run` 只打印统计不写文件。导入日志会报：
  * `hand-edited images: N` —— 真正被你改过的字（与 ROM 不同）
  * `duplicate slots re-synced ...: N` —— 同步过去的重复槽

> **注意**：导出脚本会拒绝覆盖「改过但还没导入 ROM」的 PNG（退出码 2），
> 避免手工改字被静默冲掉；确认要丢弃时才加 `--force`。
> 打包时若目录与本次渲染差异超过 200 个字形（多半是目录来自别的 ROM），
> 打包同样会中止，需要 `--force-glyph-edits` 表示「就用这个目录」。

## 导出当前 ROM 的字库

```bash
python3 tools/export_glyphs.py                # → data/glyph_png/
python3 tools/export_glyphs.py --keep-stale   # 保留目录里多余的 PNG
```
