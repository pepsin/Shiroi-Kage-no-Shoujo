# 剧本调试器（romdbg）

在模拟器里一路按 A 走到要验证的那句话很费时间，本工具负责**看清现在演到哪、按脚本
复跑、截图**，全部是**只读**操作：

```bash
python3 tools/romdbg.py list --entry 500 --start 195 --count 16   # 按引擎播放顺序列对白行
python3 tools/romdbg.py find --text 病死的                        # 反查在哪一条目/第几行
python3 tools/romdbg.py where --state work/dbg/xxx.ss1            # 报告存档里正在演哪一行
python3 tools/romdbg.py play --state work/dbg/xxx.ss1 --frames 1500 \
        --keys "A@120:4 A@240:4" --shot-every 60                   # 无头复跑 + 逐步截图
```

> ⚠️ **本工具不提供「跳到任意一行」，也请不要再实现「文本级注入」。**
> 唯一可行的做法是把目标行塞进「当前已载入剧本」的行表里——背景、在场人物、分支标志
> 全部还是当前那一幕的。它看着像跳过去了，实际什么都没验证到，只会**掩盖真问题**：
> 卡死、花屏、剧情不对，都可能被这种假跳转骗过去（这个坑踩过一次，见
> `docs/存档卡死分析.md`）。要看某句话，只能在游戏里正常走到，或者用游戏内存档
> + `play` 复跑。
>
> 真正的剧情跳转（走引擎自己的场景切换）需要「槽号 ↔ 场景」的对应关系，
> 见第五节，**尚未做成**。

## 一、引擎侧的已知事实

### 资源在内存里的样子

剧本资源（FAT 条目）解压后：

| 偏移 | 内容 |
|---|---|
| `0x000` | 头部（各条目完全相同的模板） |
| `0x680` | 流程 / 标志区 |
| `0x7A0` 起 | **字符串池**：先放「行偏移表」（升序 u32，**可能奇数对齐**），后面紧跟各行文本（u16 码位 + `0x0000` 结束） |

引擎把整条资源解压进 **EWRAM `0x02030300`**，并在 `0x02003F24` 维护描述符：

| 地址 | 含义 |
|---|---|
| `0x02003F24` | 字符串池基址（`0x02030300 + 0x7A0`） |
| `0x02003F28` | ROM 指针（恒为 `0x08651BF0`） |
| `0x02003F2C` / `0x02003F30` | 资源缓冲基址（`0x02030300`） |
| `0x02003F34` | keyB |
| `0x02003F38` | keyCount（本资源有多少行） |

显示时引擎从行偏移表顺序取项：`行地址 = 池基址 + u32[表项]`，游标每次 `+4`。

| IWRAM | 含义 |
|---|---|
| `0x03007C40` | 刚读完的表项偏移 `+ 2` |
| `0x03007C44` | 刚取到的**行偏移**（池内相对） |

所以运行中随时能读出「现在在演第几行」——`where` 就是读这两个值。

### 文本与显示

* 字形映射：**显示字形 = `MAP[码位 − 1]`**（所有码位）。注意本工程的工具约定是
  `code < 0x20 → MAP[code]`，与实机显示相差一格，详见 `docs/技术说明.md` 第 10 节。
  写译文时按**工具约定**（`translation.tsv` 即约定本身），`romdbg.py list` 的解码
  也已对齐同一约定，所以两边读到的字是一样的。
* 文本框一次显示 **2 行**；**A 的第一下只补完打字机，第二下才翻页**——自动按键脚本
  里每句话至少给两次 A。
* `0x0A` 是空白字形（`␣`），不是方块。
* **条目编号与剧情顺序无关**：葬礼那幕是 `e438`，日期卡分散在 e1 / e16 / e57 …
  （3月11日 = e1、3月12日 = e16、3月13日 = e57）。

## 二、无头 harness

读写内存、按键、截图由 `legacy/gbarun_dbg.c` 提供的无头 mGBA harness 完成：

```bash
make dbg        # = clang -O2 -o work/bin/gbarun_dbg legacy/gbarun_dbg.c \
                #   -I$(MGBA_HOME)/include -L$(MGBA_HOME)/lib -lmgba -lm -lpthread
```

可用的环境变量（多数由 `romdbg.py` 驱动，也可手写）：

| 变量 | 作用 |
|---|---|
| `GBARUN_STATE` | 先载入一份 `.ssN` 即时存档 |
| `GBARUN_SAVE` | 跑完存一份 `.ssN`（注意：**不是**卡带存档，别和 `--savfile` 混） |
| `GBARUN_SAVFILE` | 把卡带存档（EEPROM 8 KB）喂给模拟器；不加的话游戏跑在**空白卡带**上（`mCoreAutoloadSave()` 在本 harness 里永远失败） |
| `GBARUN_CALL` | 到帧号时调用某个地址（带参数），可多组 |
| `GBARUN_POKE` | 到帧号时往地址写值 |
| `GBARUN_READ` | 到帧号时读地址 |
| `GBARUN_WATCH` | 监视地址，变化即打印（排查游标就靠它） |
| `GBARUN_LOGLOAD` / `GBARUN_LOGSTORE` | 读写追踪，输出到 `/tmp/gbarun_mem.txt` |
| `GBARUN_SAMPLE` | 单步采样 PC（4 KB 直方图 + 最近 PC 序列），用来定位「卡在哪」 |
| `GBARUN_SEARCH` | 在内存里搜字节串 |
| `GBARUN_RAMSNAP` | 到帧号时 dump 一段 RAM（EWRAM/IWRAM） |
| `GBARUN_SHOT_EVERY` | 每 N 帧截一张 `.ppm` |
| `GBARUN_TRACE="loF:hiF"` | 执行路径 trace（帧区间），配 `GBARUN_LOGPC="lo:hi"` 限 PC → `/tmp/gbarun_trace.txt`；`GBARUN_TRACE_ALL=1` 关掉连续同 PC 折叠 |
| `GBARUN_PCTRACE="addr:len"` | 某地址的值一变就打印改它的 PC/LR → `/tmp/gbarun_pctrace.txt`（"谁写了这个变量"） |
| `GBARUN_SAMPLE_RANGE="lo:hi"` | `GBARUN_SAMPLE` 只统计该 PC 区间，用来把 4 KB 一档切细 |
| `GBARUN_SAMPLE_KEY=A` | 采样期间一直按住该键，采"按键之后"的状态而不是空闲态 |

## 三、命令参考

| 命令 | 说明 |
|---|---|
| `list --entry E [--start N] [--count M]` | 按**引擎播放顺序**列出对白行（实机文本，非主表顺序） |
| `find --text "..."` | 反查某句话在哪一条目、第几行（较慢，要解压全部条目，约 50 s） |
| `dispatch --entry E` | 查该条目的钥匙 `(keyCount, keyA, keyB)` |
| `where --state X.ss1` | 报告存档里正在演哪一行 |
| `base` | 冷启动到固定帧，存一份基准存档 `work/dbg/base.ss1`（给 `play` 当前点） |
| `shot <src.ppm> <dst.png>` | `.ppm` 转 PNG（放大、最近邻） |
| `play --state X.ss1 --keys "A@120:4"` | 无头复跑 + 定时截图 |
| `raw ...` | 透传其余 harness 参数 |

`--keys` 语法：`按键@帧号:次数`，多组用空格分隔，例如 `"A@120:4 A@240:4"`。

### 自动通关（autoplay + 加速）

`romdbg play` 只适合"按绝对帧号跑一小段"，**通关**要用脚本驱动版 harness：

```bash
make play-tool                                    # → work/bin/autoplay
AUTOPLAY_GLYPHMAP=work/glyph_map.ext.csv \
GBARUN_STATE=work/play/ck56.ss1 ./work/bin/autoplay \
    "侦探神宫寺三郎 - 白影的少女 (简中).gba" work/play/exp132.txt work/play
```

脚本是一行一条命令的相对时间序列（`wait/press/hold/mash/shot/save/load/msg`），
外加一组**按内存状态反应**的命令，用来代替"睡固定帧数"：
`if_eq / if_ne / if_live / if_frame_gt`、`goto / label`、
`wait_eq / wait_ne / wait_chg`、`expect_entry`、
`mash_stall <键> <上限> <等翻页帧数>`（对白推进：按一下 → 等游标对
`0x03007C40/0x03007C44` 变化，两次没动静=停）、
`nav / navc / navsoft <项号>`（菜单导航；`navsoft` 无菜单时静默跳过、不会 fatal）、
`r32 <地址> [标签]`（探针，打到 stderr）、`turbo <N>`。

**加速（mGBA fast-forward）**：无头 harness 本来就不锁帧（约 3300 fps ≈ 55 倍速），
`turbo 1` 再让 mGBA 用 dummy renderer 接管 VRAM/调色板/OAM 写入
（即前端"快进"用的同一招），实测再快约 7%——瓶颈是 GBA 解释器本身，不是画面。
`turbo` 只影响画面，不影响模拟结果；每次 `shot`/`save` 会自动把软件渲染器接回来重画一帧，
截图和即时存档逐字节一致（已验证 `turbo 0/1` 截图 sha256 相同）。
真正省时间的是**别睡固定帧数**：`mash_stall` / `wait_eq` 这类按状态推进，
同样的剧本能用一半以下的帧数走完；
带 `if_frame_gt` + `goto` 的循环还能让一段剧情无人值守地跑完。

搜索模式（書斎等）备忘：十字光标 = `0x07000000`，`0x40000000|(x<<16)|y`，
方向键按 16 px 走；`0x02015160` 是 UI 标志（0=对白，2=菜单/自动演出，4=选择提示）。
调查柜子抽屉会进"要查第几层"网格（2×2，方向键移动菱形光标，A 确认），
问完一层会出"要怎么做！查其他层/暂不移动"（游标 `0x02012F88`，第 1 项=暂不移动退出）。
書斎那幕的**抽屉钥匙**在右书架左缘中段（锚定 (0,0) 后 DOWN×3、RIGHT×11，约 (178,46)）调查；
拿到钥匙后抽屉第四层才能开（相册 → 亜希的照片 → 结束搜索）。

事务所自由行动期的**指令菜单**是环形（游标 `0x0200DF94`），实测
`0=抽煙 1=洋子 2=周囲 3=交談 4=移動 5=持有物`；有人在场时「移動」会被拒
（"总不能把她丢着不管吧"/"就在这里和春菜还有洋子聊聊天吧"），要先「交談」把在场的人聊完。
⚠️ **这个菜单是"列表在固定高亮行下面滚动"**：按 DOWN 时移动的是整列文字，
高亮框始终停在屏幕上同一行（第 3 行）。看截图逐格比对会误以为"环序变了"，
其实序号含义固定；用 `navcmd <idx>` 的序号就是动作编号。
⚠️ 菜单只在 **`uiflag=2` 且剧本停在 `0x03007C44 == 0x50`** 的"一拍"上接受输入；
平时对话盒还在翻页时按方向键是**没反应**的（`navcmd` 会报 `no move`）。
这类"按住 A 才翻页"的长对话要用 `hold A 40` 反复推，推到那个节拍再动菜单 ——
只按 4 帧的 `mash_stall` 会一直在同一段 6 行对白里绕圈。
推理题（`0x02013340`）一题有 6 个候选、屏幕只显示 4 行的窗口，
`navi <idx>` 选中的是**候选序号**不是显示行号。
3/11 夜"熊野的样子为什么奇怪"那道（推理 No.7/No.8，条目 322）候选顺序是
`0 并无特别 / 1 身体不适 / 2 害怕幽灵 / …`，**正确答案 = `navi 2`（害怕幽灵）**；
选错会走"推理不顺利→时间到→重来"的循环（条目 322 → 5 → 467），选对才接
熊野告辞、进入下一段。
**路地那道（推理 No.9，条目 324）的正确答案 = `navi 5`（无法做出判断）** ——
选对才会接"熊野正式委托调查小悠 → 春菜告辞 → 睡觉 → 3/12 白天"，
选错就一直在"原来是我多心了 → 终究没能做出来 → 重来"里循环。
它的候选表口径又不一样：`0x02013340` 是候选序号，列表**开在中段（=4）**、
方向键可用的窗口只有 ~150 帧、而且落在 `engineLive()` 为假的装载瞬间；
窗口里"按一下走 1 格"、窗口一过就冻住，只剩 A 会把默认项（8 是错觉）确认掉。
下一页的推理题（条目 316，"她到底是谁"，候选 哲司之妻/哲也的母亲/…）还没解。
推理题的判定行：走到 `0x03007C44 == 0x502`（"、奇怪的理由是！"那行）时列表才可导航，
（补充：路地那道 推理 No.9 口径又不一样 —— `0x02013340` 装的是**候选序号**，列表
**开在中段（=4）**、"能按方向键"的窗口只有 ~150 帧、而且出现在 `engineLive()` 为假的
装载瞬间；窗口里"按一下方向键大约走 1 格"，窗口一过游标就冻住，只剩 A 能把默认项
（8 是错觉）确认掉。`drive` 的推理分支就是照这个写的：对白推一页后按 **1 帧粒度盯 500 帧**。）
早一帧按 DOWN 光标不动；`navsoft`（0x02012F88）在这道题上**无效**，必须用
`navi`/`navisoft`（0x02013340）。

一个能无人值守跑一段的驱动骨架（`navcmd` 未移动时**不会**按 A，所以自动演出
（也是 uiflag=2）里当它不存在就行）：

**更省事的是 harness 里的 `drive`**（这轮新加，专治自由行动期）：

```
drive <帧数> <动作1,动作2,...> [选择项=1] [推理项=-1]
```

`推理项` 给具体序号 = 每次遇到推理题都选它；给 `-2` = **自动爆破**：每次遇到就换一个
（0,1,2,…），用来试不知道正确答案的题。

它按下面三条规则自己跑：

- `uiflag=4` → 先试推理表（`0x02013340`，给 `推理项` 时才试），失败再退回选择表
  `0x02012F88` 选第 `选择项` 项；
- `uiflag=2` **且按一下 DOWN 光标真的会动**（真指令菜单，自动演出里是死的）→
  按轮换表取下一个动作并按 A；
- 其它情况 → **按住 A 40 帧**再等 200 帧（这游戏的整页对白吃"按住"，
  4 帧的点按会被吞，`mash_stall` 因此一直在同一段 6 行里绕）。

例：`drive 400000 1,2,1,3,1,4 1` = 西新宿路地里轮流「春菜/周囲/春菜/移動/春菜/持有物」。

手写版骨架（逻辑一样，便于插探针）：

```
label loop
if_frame_gt 900000 done
if_eq 0x02015160 4 choice     # 选择提示
if_eq 0x02015160 2 maybe_menu # 指令菜单 / 自动演出
hold A 40                     # 长对白要按住
wait 200
goto loop
label maybe_menu
navcmd 3                      # 3=交谈；不是指令菜单就什么都不做
wait 300
hold A 40
wait 200
goto loop
label choice
navsoft 1 10                  # 第 2 项 = 不是/结束搜索（别选第 1 项，会进存档屏）
wait 250
hold A 40
wait 200
goto loop
label done
save work/play/ck73.ss1
```

> 存档屏（「记录数据吗」选成"是"就会进去）里 B 不退；正确退出是
> `B B SELECT B DOWN B LEFT B`，出现「保存·即将结束载入 这样可以吗？是的/不是」
> 后按 **A**（高亮要落在「是的」上，必要时先 LEFT/UP 一下）。

### 新宿地图（移動）界面

3/12 起会出现城市地图（`SHINJUKU CITY` / `NAKANO CITY` / `SHIBUYA CITY`），
操作口径和别的界面都不一样：

* **信息框要先按 A 清掉**（"这里就是当前地点。没有移动的必要。"那种），
  清掉之后方向键才吃 —— 否则怎么按地图都不动（曾经在这里空转很久）；
* 方向键**滚地图**，光标停在屏幕固定处；光标底下的地标名会变**橙色**；
* 在地标上按 A → 弹「要去X看看吗！去吧／还是不去」（普通选择表，第 1 项=去吧）；
* 已见地标：`新宿中央公園` / `新宿駅西口` / `神宮寺事務所` / `大河原家` /
  `コーポ中野ハイツ`（= 中野公寓楼，亜希的住处）。

一趟可复现的走法（`ck121` 起，走到亜希公寓）：

```
press A          # 清信息框
wait 300
press UP         # 光标落到 コーポ中野ハイツ
wait 150
press A          # 出「要去中野公寓楼看看吗！」
wait 400
navsoft 0 8      # 「去吧」
```

### 不开模拟器：直接看 `.ssN`

不跑 harness 也能读存档 —— `tools/state_inspect.py`（只读、不需要
`work/glyph_map.ext.csv`，只依赖 `data/glyph_map.csv` 与 ROM 字体表）：

```bash
python3 tools/state_inspect.py where x.ss2                  # 引擎在演哪一行 + 关键字节
python3 tools/state_inspect.py peek  x.ss2 0x020150B4,16    # 按地址读 RAM/IO
python3 tools/state_inspect.py rows  x.ss2 260              # 存档自带行表里的全部行
python3 tools/state_inspect.py diff  a.ss2 b.ss4            # 两份存档逐字节差
python3 tools/state_inspect.py scan  x.ss2 8d150000         # 在 RAM 里搜字节串
```

⚠️ `where` 报的「游标」读的是 IWRAM `0x03007C40`/`0x03007C44`。这两个地址在
**栈区**里：如果快照正好落在某个函数调用的中间，读出来的就是栈帧而不是游标
（`docs/存档卡死分析.md` 第零节，ss1 就是这样）。用之前先和「行表 + 0x125B」核对。

## 四、真正的剧情跳转（**尚未做成**）

### 已知的入口

| 地址 | 作用 |
|---|---|
| `0x08004EE4`（Thumb） | `loadScript(keyCount, keyA, keyB)`：线性搜索 **ROM file `0x15C004`** 的 **509 × 8 字节**分发表 `{s16 entryId, s16 keyCount, s16 keyA, s16 keyB}`，`index = entryId − 1`，命中后取条目地址 |
| `0x08014684` | `getEntryAddress(entryId)`：由条目号取 FAT 地址 |
| `0x0801ED50`（Thumb） | 场景切换：查 ROM 表 `0x0807D870` 的槽 → 拷到 EWRAM `0x02014D90` → 调 `loadScript` |

### 缺的那块：槽号 ↔ 场景

`0x0807D870` 那张表里存的是「槽」，但我们还没有「槽 ↔ 剧情场景」的对应关系。
补上之后就能从「当前在演第几幕」直接索引到目标场景，调用引擎自己的切换流程，
背景 / 人物 / 标志才会一起就位。

### 三个记录在案的负结果（别再走一遍）

1. **文本级注入**：把目标行写进当前行表 + 改游标。看着能用，实则背景/人物/标志全不对，
   会掩盖真问题 —— 已从工具里删除。
2. **直接 `GBARUN_CALL` 调 `0x08004EE4(31,1,1)`** → PC 跳到 BIOS 崩溃。
   后来给「裸写 PC」加了 mGBA prefetch 刷新（`cpu->prefetch[0]/[1]`）仍然崩。
   结论：loader 依赖引擎自己那套场景切换上下文，不能隔空调。
3. **FAT 重定向**（把 `FAT[438]` 指向 `FAT[500]` 的内容做成测试 ROM）→ 白屏。
   条目内容与它期望的流程 / 标志区是配套的，单换内容不成立。

### 跳行命令 `skiprows` / `gotorow`（已实现）

`legacy/autoplay.c` 里加了两条：

```
skiprows <k>   # 相对当前行前进/后退 k 行（推荐）
gotorow <N>    # 跳到本资源第 N 行（需要知道行表起点，一般不如 skiprows 稳）
w32 <addr> <v> # 直接写 32 位内存（改标志/游标用）
```

要点（都是踩过的坑）：

* 引擎的 `0x03007C40` = **行表项的池内偏移 + 2**，所以相对跳行就是
  `目标表项 = 池基址 + (cur - 2 + 4k)`，再把它读出来的 u32 写进 `0x03007C44`；
* **行表可能奇数对齐**，`GBAView32` 对未对齐地址会做 ARM 旋转（读出来是 `0x49000021`
  这种"转过的"值），必须用 `GBAView8` 自己拼小端；
* 实测命中：`ck150 + skiprows 14` → 行偏移 `0x2281` =「我把自己的名片递给佐佐木」；
  `+40` → `0x24DB` =「」谁知道呢“““『」；
* **但光跳进去不够**：引擎播完那一行后仍会跳回选择菜单（因为选择项/标志没设），
  所以跳行适合"看一眼后面的剧本"，不适合当作推进手段。

### ★ 剧本 VM 格式与「递名片」分支的真正入口（子代理解出，已实测）

完整笔记见 `work/scratch/entry500_format.md`。要点：

* 资源布局：`0x0000` 头部 / `0x0000-0x125B` **脚本字节码** / `0x125B` 行偏移表 / `0x163F` 起行文本。
  **JP 与 CN 在字节码区逐字节相同** → 「递名片进不去」**不是汉化造成的**。
* VM：脚本 IP = EWRAM `0x0200E014`，池基址 `0x0200E06C`。指令：`01 <u16 row> <u8>` 显示行、
  `47 <u8 01> <u16 row>` 说话人、`80/81` 分页、`9E <u32>` 子程序、`43 <u16 idx>` 跳场景表、
  `54 <u8 n> <u16 rel>` **弹菜单**。
* 菜单项记录 6 字节 `<u8 tag><u16 payload><u8 flags><u16 label_row>`，选中后从记录 `+6` 执行；
  `tag=0xFE` 无条件；**`tag=0xB1,payload=k` ⇒ 需 `EWRAM[0x02012EB0+k] & 0xF != 0`**。
* hub 菜单（池 `0x2BD`）的 4 个选项：
  `FE`→行10 打听亜希的事、`FE`→行22 和对方闲聊、`FE`→行126 询问佐佐木的事、
  **`B1 0F`→行15 谈谈自己的事 = 名片块（行 134/135/136/137/138）**。
  前三项走完都回菜单，所以「询问佐佐木 ×2」永远到不了名片。
* **解锁：把 `0x02012EBF` 写成非 0**（B1[15]），菜单变 4 项；
  光标 `0x02012F88`，2×2 布局：左上 打听亜希的事 / 右上 和对方闲聊 / 左下 询问佐佐木的事 /
  **右下 谈谈自己的事**（`DOWN` 0→2，`RIGHT` 2→3，`A`）。
  注意：菜单列表是**缓存的**，已经画出来时要先选一项让它重建。
* 运行时结构：可选项数 `0x02012FA0`、光标 `0x02012F88`、选项记录地址表 `0x02013310+4i`。
* 复现用即时存档：`work/scratch/card138.ss1`（载入即见「我把自己的名片递给佐佐木」）。

**新命令 `navfast <idx>`**：菜单大约 5 秒不操作就会自己按默认项走，所以加了这条
"提示一出现就立刻选"的命令（每步只按 4 帧键、8 帧等，优先 RIGHT）。
