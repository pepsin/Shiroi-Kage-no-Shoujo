# 剧本调试器（romdbg）

在模拟器里一路按 A 走到要验证的那句话很费时间，本工具负责**看清现在演到哪、按脚本
复跑、截图**，全部是**只读**操作：

```bash
python3 tools/romdbg.py list --entry 500 --start 195 --count 16   # 按引擎播放顺序列对白行
python3 tools/romdbg.py find --text 病死的                        # 反查在哪一条目/第几行
python3 tools/romdbg.py where --state work/dbg/xxx.ss1            # 报告存档里正在演哪一行
python3 tools/romdbg.py play --state work/dbg/xxx.ss1 --frames 1500 \
        --keys "A@120:4 A@240:4" --shot-every 60                   # 无头复跑 + 逐步截图
```

> ⚠️ **本工具不提供「跳到任意一行」，也请不要再实现「文本级注入」。**
> 唯一可行的做法是把目标行塞进「当前已载入剧本」的行表里——背景、在场人物、分支标志
> 全部还是当前那一幕的。它看着像跳过去了，实际什么都没验证到，只会**掩盖真问题**：
> 卡死、花屏、剧情不对，都可能被这种假跳转骗过去（这个坑踩过一次，见
> `docs/存档卡死分析.md`）。要看某句话，只能在游戏里正常走到，或者用游戏内存档
> + `play` 复跑。
>
> 真正的剧情跳转（走引擎自己的场景切换）需要「槽号 ↔ 场景」的对应关系，
> 见第五节，**尚未做成**。

## 一、引擎侧的已知事实

### 资源在内存里的样子

剧本资源（FAT 条目）解压后：

| 偏移 | 内容 |
|---|---|
| `0x000` | 头部（各条目完全相同的模板） |
| `0x680` | 流程 / 标志区 |
| `0x7A0` 起 | **字符串池**：先放「行偏移表」（升序 u32，**可能奇数对齐**），后面紧跟各行文本（u16 码位 + `0x0000` 结束） |

引擎把整条资源解压进 **EWRAM `0x02030300`**，并在 `0x02003F24` 维护描述符：

| 地址 | 含义 |
|---|---|
| `0x02003F24` | 字符串池基址（`0x02030300 + 0x7A0`） |
| `0x02003F28` | ROM 指针（恒为 `0x08651BF0`） |
| `0x02003F2C` / `0x02003F30` | 资源缓冲基址（`0x02030300`） |
| `0x02003F34` | keyB |
| `0x02003F38` | keyCount（本资源有多少行） |

显示时引擎从行偏移表顺序取项：`行地址 = 池基址 + u32[表项]`，游标每次 `+4`。

| IWRAM | 含义 |
|---|---|
| `0x03007C40` | 刚读完的表项偏移 `+ 2` |
| `0x03007C44` | 刚取到的**行偏移**（池内相对） |

所以运行中随时能读出「现在在演第几行」——`where` 就是读这两个值。

### 文本与显示

* 字形映射：**显示字形 = `MAP[码位 − 1]`**（所有码位）。注意本工程的工具约定是
  `code < 0x20 → MAP[code]`，与实机显示相差一格，详见 `docs/技术说明.md` 第 10 节。
  写译文时按**工具约定**（`translation.tsv` 即约定本身），`romdbg.py list` 的解码
  也已对齐同一约定，所以两边读到的字是一样的。
* 文本框一次显示 **2 行**；**A 的第一下只补完打字机，第二下才翻页**——自动按键脚本
  里每句话至少给两次 A。
* `0x0A` 是空白字形（`␣`），不是方块。
* **条目编号与剧情顺序无关**：葬礼那幕是 `e438`，日期卡分散在 e1 / e16 / e57 …
  （3月11日 = e1、3月12日 = e16、3月13日 = e57）。

## 二、无头 harness

读写内存、按键、截图由 `legacy/gbarun_dbg.c` 提供的无头 mGBA harness 完成：

```bash
make dbg        # = clang -O2 -o work/bin/gbarun_dbg legacy/gbarun_dbg.c \
                #   -I$(MGBA_HOME)/include -L$(MGBA_HOME)/lib -lmgba -lm -lpthread
```

可用的环境变量（多数由 `romdbg.py` 驱动，也可手写）：

| 变量 | 作用 |
|---|---|
| `GBARUN_STATE` | 先载入一份 `.ssN` 即时存档 |
| `GBARUN_SAVE` | 跑完存一份 `.ssN`（注意：**不是**卡带存档，别和 `--savfile` 混） |
| `GBARUN_SAVFILE` | 把卡带存档（EEPROM 8 KB）喂给模拟器；不加的话游戏跑在**空白卡带**上（`mCoreAutoloadSave()` 在本 harness 里永远失败） |
| `GBARUN_CALL` | 到帧号时调用某个地址（带参数），可多组 |
| `GBARUN_POKE` | 到帧号时往地址写值 |
| `GBARUN_READ` | 到帧号时读地址 |
| `GBARUN_WATCH` | 监视地址，变化即打印（排查游标就靠它） |
| `GBARUN_LOGLOAD` / `GBARUN_LOGSTORE` | 读写追踪，输出到 `/tmp/gbarun_mem.txt` |
| `GBARUN_SAMPLE` | 单步采样 PC（4 KB 直方图 + 最近 PC 序列），用来定位「卡在哪」 |
| `GBARUN_SEARCH` | 在内存里搜字节串 |
| `GBARUN_RAMSNAP` | 到帧号时 dump 一段 RAM（EWRAM/IWRAM） |
| `GBARUN_SHOT_EVERY` | 每 N 帧截一张 `.ppm` |

## 三、命令参考

| 命令 | 说明 |
|---|---|
| `list --entry E [--start N] [--count M]` | 按**引擎播放顺序**列出对白行（实机文本，非主表顺序） |
| `find --text "..."` | 反查某句话在哪一条目、第几行（较慢，要解压全部条目，约 50 s） |
| `dispatch --entry E` | 查该条目的钥匙 `(keyCount, keyA, keyB)` |
| `where --state X.ss1` | 报告存档里正在演哪一行 |
| `base` | 冷启动到固定帧，存一份基准存档 `work/dbg/base.ss1`（给 `play` 当前点） |
| `shot <src.ppm> <dst.png>` | `.ppm` 转 PNG（放大、最近邻） |
| `play --state X.ss1 --keys "A@120:4"` | 无头复跑 + 定时截图 |
| `raw ...` | 透传其余 harness 参数 |

`--keys` 语法：`按键@帧号:次数`，多组用空格分隔，例如 `"A@120:4 A@240:4"`。

## 四、真正的剧情跳转（**尚未做成**）

### 已知的入口

| 地址 | 作用 |
|---|---|
| `0x08004EE4`（Thumb） | `loadScript(keyCount, keyA, keyB)`：线性搜索 **ROM file `0x15C004`** 的 **509 × 8 字节**分发表 `{s16 entryId, s16 keyCount, s16 keyA, s16 keyB}`，`index = entryId − 1`，命中后取条目地址 |
| `0x08014684` | `getEntryAddress(entryId)`：由条目号取 FAT 地址 |
| `0x0801ED50`（Thumb） | 场景切换：查 ROM 表 `0x0807D870` 的槽 → 拷到 EWRAM `0x02014D90` → 调 `loadScript` |

### 缺的那块：槽号 ↔ 场景

`0x0807D870` 那张表里存的是「槽」，但我们还没有「槽 ↔ 剧情场景」的对应关系。
补上之后就能从「当前在演第几幕」直接索引到目标场景，调用引擎自己的切换流程，
背景 / 人物 / 标志才会一起就位。

### 三个记录在案的负结果（别再走一遍）

1. **文本级注入**：把目标行写进当前行表 + 改游标。看着能用，实则背景/人物/标志全不对，
   会掩盖真问题 —— 已从工具里删除。
2. **直接 `GBARUN_CALL` 调 `0x08004EE4(31,1,1)`** → PC 跳到 BIOS 崩溃。
   后来给「裸写 PC」加了 mGBA prefetch 刷新（`cpu->prefetch[0]/[1]`）仍然崩。
   结论：loader 依赖引擎自己那套场景切换上下文，不能隔空调。
3. **FAT 重定向**（把 `FAT[438]` 指向 `FAT[500]` 的内容做成测试 ROM）→ 白屏。
   条目内容与它期望的流程 / 标志区是配套的，单换内容不成立。

## 五、排障

| 现象 | 原因 / 处理 |
|---|---|
| `base` 生成的存档进去就黑屏 | 基准帧不对，换一帧，或先用 mGBA 手存一个 `.ss1` 传给 `--base-state` |
| 载入 `.ssN` 后游戏「看着在动但不推进」 | 先排除快照问题：换一份新鲜存档对比，见 `docs/存档卡死分析.md` |
| 同一句话按一次 A 不翻页 | 正常：第一下补完打字机，第二下才翻页；自动按键脚本每句至少两次 A |
| `find` 很慢 | 它要解压全部条目，约 50 s，属正常 |
| 存档载入报错 / 画面乱字 | `.ssN` 与 ROM 版本相关，改过 ROM 后请重新生成基准存档 |
| 存档界面里没有文件 | harness 没喂卡带存档：加 `GBARUN_SAVFILE=<x.sav>` |
