# 翻译作业流程（translation pipeline）

> 主表：`data/translation.tsv`（45488 行，CRLF，列 = entry / idx / offset / n_codes / n_bytes / jp_text / translation）
> 规范：`data/translation_rules.md`　词表：`data/glossary.tsv`　原则：`AGENT.md`

## 一、工具

| 命令 | 作用 |
|---|---|
| `python3 tools/tm.py status` | 进度总览（已译行数 / 剩余条目） |
| `python3 tools/tm.py batches --size 250 --limit 2000 --outdir work/tm/wNN` | 生成一批作业文件（只含未译行，按条目切分） |
| `python3 tools/tm.py verify <out 文件...>` | 校验译文：标点序列 / 长度 / 假名 / 结构 |
| `python3 tools/tm.py apply <out 文件...>` | 回写主表（保留 CRLF；重复原文自动套用同一译法） |
| `python3 tools/tm.py check` | 全表体检 + 缺字统计 + 长度分布 |
| `python3 tools/glyph_plan.py` | 字库测算：需要多少新字形、有多少空槽、是否必须扩表 |

## 二、作业协议

**输入**（`tm.py batches` 生成）——TSV，只含未译行：

```
rid	entry	idx	len	jp_text
3:0	3	0	11	デ～タを記録しますか！
```

**输出**（译员/子代理产出）——两列，文件名 `bNNN.out.tsv`：

```
rid	cn
3:0	要记录数据吗！
```

## 三、硬性校验（`tm.py verify` / `apply` 自动执行）

1. **标点同种类、同数量、同顺序**：`、。，！？「」『』・：；“”‘’（）〈〉《》‥□○■×＋＜＞％々`
   —— 原文有的不能删，原文没有的不能加。
2. **长度 ≤ `len`**（`len` = 原文码数），并尽量接近 `len`。
3. **无假名**（假名人名按 `data/glossary.tsv` 末节恢复成汉字）。
4. 无 TAB / 换行；`rid` 与输入一一对应。
5. 人名保留日文原写法（不简体化）。

`apply` 会**拒收**不合规的行（保持空白、写入 `work/tm/needs_fix.tsv`），不合规的行会在下一批重新出现。

## 四、效率要点

* **重复台词自动套用**：45488 行里只有 16763 条不同原文（其余是各章重复的系统提示、菜单、人名）。
  `apply` 会按 `jp_text` 把已有译文铺到所有相同原文的行上，因此实际需要人工/模型翻译的量远小于行数。
* **按条目切批**：同一批次内的行是连续对白，便于保持人称、语气、称呼一致。
* **主表是 CRLF**：`tm.py` 逐字段改写、按原行尾回写，未改动的行保持字节不变。

## 五、字库衔接

`tools/glyph_plan.py` 在翻译进行中即可随时测算：

* 译文用到的不同汉字数、其中日文字库已有的、需要新做的；
* 译文**不再引用**的字形槽（= 可复用空位）；
* 缺口 > 0 时才需要走 `docs/汉化方案设计.md` 的路线 B（整表搬迁扩容）。

新字形生成与注入见 `tools/font_patch.py`（`render` / `slots` / `inject`）。

## 七、第二类条目：无偏移表的「串池」（2025 补充，重要）

**问题**：最初 `export_script.py` 只识别「偏移表 + 字符串池」结构的条目，共 190 个。
实测发现游戏里还有 **258 个剧本条目**没有偏移表——它们的字符串是**一串 NUL 分隔的 u16 码**，
直接躺在条目数据里，而且**有的落在奇数字节偏移**上。这些条目整批被跳过，
于是实机里出现大段未翻译文本（例：e1 的人物介绍 `彼女は御苑洋子。`）。

**为何必须单独处理**：这类条目的字符串**没有索引表**，无法用 `entry_catalog` 的
`base/offset` 定位，必须扫描「连续 NUL 分隔串段」并按**常用字占比 + 假名存在**过滤掉
位图数据的假阳性（字库表 e850 之类会被误判成文本）。

**工具**：`tools/extract_pool.py`

```bash
python3 tools/extract_pool.py --dry-run    # 预览
python3 tools/extract_pool.py              # 追加到 data/translation.tsv
```

新增行在原 7 列后多一个第 8 列 `kind = pool`；此时 `offset` 是**条目内的绝对字节偏移**
（表格式条目仍是相对 base 的偏移，`kind` 留空）。

**回写**：`import_script.py` 已支持——对串池行按绝对偏移**原位改写**，
并把该槽剩余空间补 `0x0000`，因此脚本里所有引用偏移都不变。

| 项 | 数值 |
|---|---|
| 新增条目 | 257 个（e605 是输入法字典表，已排除） |
| 新增行 | 14,396 条（不同原文 7,553 条 / 84,972 字） |
| 主表规模 | 45,488 → **59,884 行** |
| 最终完成度 | **59,862 / 59,862（100%）** |

**已从主表移除的非文本行（共 15 行，不是漏译）**：

* e1489 的 4 行二进制噪声（`獲獲獲…処ぱ`）
* e605 的 11 行「假名→汉字候选」输入法字典表（`ぱひ`、`びふぶぷ`、`わ1を着先茶`…），
  译了会把中文写进文本转换表，破坏全篇渲染

这两类行**已从 `data/translation.tsv` 删除**，主表现在只剩可翻译文本，且**每行都有译文**。
`extract_pool.py` 的 SKIP 已加入 605，重新提取不会再收进来。

**姓名用字修正**：小女孩 `ゆう` 在剧本里写作汉字 **悠**（e279 `悠を探していた`），
早期按 kana 推定的「優」已全量改为「悠」（714 行）。
