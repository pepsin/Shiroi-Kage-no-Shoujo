# 翻译作业流程（translation pipeline）

> 主表：`data/translation.tsv`（45488 行，CRLF，列 = entry / idx / offset / n_codes / n_bytes / jp_text / translation）
> 规范：`data/translation_rules.md`　词表：`data/glossary.tsv`　原则：`AGENT.md`

## 一、工具

| 命令 | 作用 |
|---|---|
| `python3 tools/tm.py status` | 进度总览（已译行数 / 剩余条目） |
| `python3 tools/tm.py batches --size 250 --limit 2000 --outdir work/tm/wNN` | 生成一批作业文件（只含未译行，按条目切分） |
| `python3 tools/tm.py verify <out 文件...>` | 校验译文：标点序列 / 长度 / 假名 / 结构 |
| `python3 tools/tm.py apply <out 文件...>` | 回写主表（保留 CRLF；重复原文自动套用同一译法） |
| `python3 tools/tm.py check` | 全表体检 + 缺字统计 + 长度分布 |
| `python3 tools/glyph_plan.py` | 字库测算：需要多少新字形、有多少空槽、是否必须扩表 |
| `python3 tools/scene_index.py build/list/show/check` | **场景推进索引**：按剧情顺序重建 795 个场景（见第六节） |
| `python3 tools/export_scene_context.py` | 导出整场景的复核对（日文 ｜ 现译 + 跨行标记 + 字数预算） |
| `python3 tools/style_lint.py --top 30` | 按「倒装/翻译腔」密度给场景排序，决定下一批去哪儿（不是判定，只是排序） |

## 二、作业协议

**输入**（`tm.py batches` 生成）——TSV，只含未译行：

```
rid	entry	idx	len	jp_text
3:0	3	0	11	デ～タを記録しますか！
```

**输出**（译员/子代理产出）——两列，文件名 `bNNN.out.tsv`：

```
rid	cn
3:0	要记录数据吗！
```

## 三、硬性校验（`tm.py verify` / `apply` 自动执行）

1. **标点同种类、同数量、同顺序**：`、。，！？「」『』・：；“”‘’（）〈〉《》‥□○■×＋＜＞％々`
   —— 原文有的不能删，原文没有的不能加。
2. **长度 ≤ `len`**（`len` = 原文码数），并尽量接近 `len`。
3. **无假名**（假名人名按 `data/glossary.tsv` 末节恢复成汉字）。
4. 无 TAB / 换行；`rid` 与输入一一对应。
5. 人名保留日文原写法（不简体化）。

`apply` 会**拒收**不合规的行（保持空白、写入 `work/tm/needs_fix.tsv`），不合规的行会在下一批重新出现。

## 四、效率要点

* **重复台词自动套用**：45488 行里只有 16763 条不同原文（其余是各章重复的系统提示、菜单、人名）。
  `apply` 会按 `jp_text` 把已有译文铺到所有相同原文的行上，因此实际需要人工/模型翻译的量远小于行数。
* **按场景切批**（推荐）：见第六节。批次应是**一个场景的连续对白**，
  而不是"按条目切 250 行"——一段对话被切断，人称与语序就无从判断。
* **主表是 CRLF**：`tm.py` 逐字段改写、按原行尾回写，未改动的行保持字节不变。

## 五、字库衔接

`tools/glyph_plan.py` 在翻译进行中即可随时测算：

* 译文用到的不同汉字数、其中日文字库已有的、需要新做的；
* 译文**不再引用**的字形槽（= 可复用空位）；
* 缺口 > 0 时才需要走 `docs/汉化方案设计.md` 的路线 B（整表搬迁扩容）。

新字形生成与注入见 `tools/font_patch.py`（`render` / `slots` / `inject`）。

## 六、场景推进索引（精修按场景作业）

主表是**逐显示行**的，而游戏把一句话拆成数行，日语的谓语又在句末。
逐行翻译必然把日文语序照抄成中文（见 `data/translation_rules.md` 一.13）。
所以精修的单位不是"行"，也不是"条目"，而是**场景**。

`tools/scene_index.py` 从主表重建剧情顺序并切场景：

```bash
python3 tools/scene_index.py build --report    # 生成 data/scenes.tsv + data/scene_lines.tsv
python3 tools/scene_index.py list --kind scene # 场景清单（id / 行数 / 地点 / 在场人物）
python3 tools/scene_index.py show 3.0          # 逐行读一个场景（日文 ｜ 现译）
python3 tools/scene_index.py check             # 101,795 行是否全部归属、pos 是否连续
```

* `data/scenes.tsv`：795 个场景（剧情 625 / 问答分支 136 / 资料 14 / STAFF 18 / 彩蛋 2），
  字段 `scene / kind / entry / idx 范围 / rows / codes / 地点 / 在场 / note`。
* `data/scene_lines.tsv`：每行 → `scene / pos / join`。**`join`** 标出一句话怎么跨行：
  `>` 接下一行，`<` 承接上一行，`<>` 中间行，`-` 本行收尾。
  全表 **42,067 行（41%）是中间行**——它们单独看不成立，必须连着整句改语序。

导出成批复核文件（整场景 + 跨行标记 + 字数预算）：

```bash
python3 tools/export_scene_context.py --entries 1-20 --out work/scenes/e1_20.tsv
python3 tools/export_scene_context.py --flagged --limit 40 --out work/scenes/f1.tsv
python3 tools/export_scene_context.py --scene 3.0        # 直接打到终端
```

输出列：`scene / entry / idx / pos / join / len / jp_text / translation / note`，
场景之间空行分隔。`--flagged` 只挑命中"疑似倒装/翻译腔"特征（`被`、`有着/的存在`、
句尾光杆动词、语气词、残留假名、连词填充）的场景。

**作业顺序**：先通读整个场景（`show` 或导出的块），确认说话人、地点、事件先后，
再逐行调语序；改完用 `apply_cn_patch.py` 回写，然后
`python3 tools/scene_index.py build && python3 tools/scene_index.py show <场景>` 复读验收。

### 6.3 同句异译归并（2025 收尾）

"一行一行翻 + 多轮局部精修"必然留下同一句日文多种译法。这类不一致是玩家觉得
"词不达意"的重要来源，先后做了四轮：

1. **多数派归并**（第 12 轮）：同一句里占绝对多数的写法，覆盖零星写法（446 → 102 条）。
2. **逐条定稿**（第 13 轮）：剩 102 条逐条人工定（102 → 1 条）。
3. **跨场景同句**（第 15 轮）：`佐藤亜希の行方に関する / 手掛かりが得られると`
   这类"第一行把话说尽、第二行孤悬"的断句错误，按场景定稿。
4. **权威合并**（第 21 轮）：以 25 个已精修条目为权威，把全表漂移拉回定稿译法
   （64 → 1 条）。

**`』様＋／』さん＋` 这类记号的译法**：剧本用 `』様＋` 表示「名字后加「様」」、
`』さん＋` 表示「名字后加「さん」」，中文没有对应构件，直译成「大人＋」读不通。
已定：`」“““』様＋じゃ / 、なかったのか！『` → 「」“““』大人＋您 / 、难道不是吗！『」。
`』様＋“““！`（e21:453，len=7）放不下同样写法，保留 `』氏＋“““！`（旧译），
属**有意保留的少数写法**（全表仅此 1 处）。

**唯一保留的例外**：`見つからなかった，` 的 3 行按上下文分别写作
「找到，」（什么都没/找到）、「都不见踪影，」（身影没找到）、「的发现，」
（没什么特别/的发现）——机械合并会把中文读破，故有意保留。

**又一类跨场景同句**：`、ええ。とても頼りに / 、なっていますよ『` 在 9 个场景里
被逐行直译成「、是的。非常依赖 / 、一直依赖着呢『」（动词落在末行、读不通），
统一改为「、是的。他真的很 / 、依赖您呢『」。用 `style_lint.py` 的 verb-tail
命中可以批量抓这类"同句被切两行、译错就错一片"。

另外做了两次全局一致性修正（不算场景）：
* `work/scenes/patch_kumasan_norm.tsv` 等 —— 称呼统一（见第八节 9.1）；
* `work/scenes/patch_ctrl_dup*.tsv` —— 人物资料行的顿号重复（见 `docs/打包流程.md` 14.7）。

### 6.4 未读场景清单（`data/scene_worklist.tsv`）

625 个剧情场景里，哪些已过、哪些没过，靠记忆追不住。`scene_worklist.tsv`
（`scene / entry / rows / status`）是可持续追踪的产物。

**覆盖率的口径很重要**：早先用手工维护的"已读条目集合"统计，得到 55.8%，但那只是
**逐段通读**过的场景；按"**该条目的译文被任何一轮精修改动过**"统计（即从全部补丁
文件反推），覆盖率到 2025 收尾时是 **625 / 625 = 100%**，其中 `done` 621 个
（译文确实改过）、`reviewed` 4 个（逐行读过、判定无需改动，见
`data/scene_reviewed.tsv`：454.0 / 456.0 / 456.1 / 461.0）。

四种状态由 `tools/worklist.py` 统一判定，不再靠记忆：

| status | 含义 |
|---|---|
| `done` | entry 出现在任一补丁文件的某一行里——译文被改过 |
| `reviewed` | 列在 `data/scene_reviewed.tsv`——逐行对过日文，判定不必改 |
| `todo` | 还没看过的剧情场景（当前 **0**） |
| `n/a` | 非剧情（系统提示、问答、人物资料、制作名单、密码页） |

生成方式：扫描 `work/scenes/patch*.tsv`、`work/tm/w*/*.out.tsv`、`work/batches/*.clean.tsv`
里的 `(entry, idx)` 取 `done`，再叠加 `scene_reviewed.tsv` 的 `reviewed`。
`done` 和 `reviewed` 故意分开：前者代表"改过"，后者代表"读过但没动"，
避免"覆盖率达到 100%"被误读成"每个场景都重写过"。

```bash
python3 tools/worklist.py build   # 重算 data/scene_worklist.tsv 并打印覆盖率
python3 tools/worklist.py check   # 校验磁盘上的 worklist 是否与补丁集同步
```

### 6.6 收尾段（entry 439–465）逐场景精修的改写要点

剩下的 `todo` 场景集中在结局前后，多是重症／生离死别的重头戏，冷峻笔法在这里最容易
写坏。第 66–69 批（20 个场景、359 行）总结出的固定处理：

* **去"的"堆叠**：`是对愚蠢的我的天罚` → 「是老天罚我太蠢」；`这个人是世界上最爱着悠
  的人` → 「这个人比谁都／疼悠」；`把治疗费的钱什么` → 「付治疗费的门路」（`アテ` 是
  门路不是钱）。
* **去填充词**：`现在就先任由她去说吧` → 「现在就随她说吧」；`一直在四处徘徊` →
  「永远地徘徊」；`已经先行一步赶到` → 「先赶到」；`真的非常对不起` → 「真的很对不起」。
* **日语受身改主动**：`被坏人追着他` → 「有坏人在追他」；`被亜希强烈的思念压着` →
  「拗不过亜希那份强烈的思念」。
* **日语汉字词不照搬**：`沉默支配了走廊` → 「沉默笼罩了走廊」；`仿佛在嘲笑我们一样` →
  「仿佛在嘲笑我们」。
* **重复句式保留原样**：`様ーな想いが残り／消えた` 的排比、`本物だ／本物の幽霊` 的
  叠说都按原文重复，不做"雅化"合并。
* **拆行后整句读一遍**：日语可断处未必是中文可断处——`那是个不折不扣的／是个活生生的
  少年` 合成 「那是个不折不扣的／活生生的少年」，`安心与失望交织的／我漏出了一声叹息`
  改成 「安心与失望交织在一起／我漏出一声复杂的叹息」，`倾尽全力朝男人／一边挥出拳头`
  改成 「倾尽全力朝男人／挥出一拳」。
* **`様子` 不译成"样子"**：`男の様子をうかがった` → 「留意着男人的动静」，菜单
  `様子を見る` → 「观察情况」。
* 长台词一律先按行拆好再改写，改完用 `tm.py` 的 `slots_used()` 逐行核对预算；
  为让中文自然，本轮只在 443.0 第 6 行多用一个逗号（`tm.py check` 违规 7 → 8，
  新增项已记账）。

### 6.7 叙述型段落（地の文）专项梳理（`tools/narration_blocks.py`）

对话可以一个场景一个场景地读，**叙述必须一段一段地读**：日文把一句叙述拆成好几行显示，
机器初翻是逐行做的，于是日语"宾语在前、动词殿后"的语序被照搬进中文，读起来像
「我带着不满的表情向正走出会场的女性目光停住了」那样别扭。

`tools/narration_blocks.py` 把每个剧情场景里连续的**非台词行**并成段落块：

* 判据是"整句组里没有任何引号标记（`」『「`，含 `』…＋` 的心声）且不是人名标签"，
  台词只在自己第一行带标记，所以必须先把 `>`／`<` 连起来的**句组**求出来，
  再整组判定，否则续行会被误当成叙述；
* 系统行（`デ～タを記録しますか！`／菜单选项）单独切掉，免得整张存档菜单混进段落；
* `list` 按长度或场景列出，`show` 读一个段落（日文＋现行中文＋每行预算），
  `stats` 看总量：**4,171 段 / 40,913 行**，其中「手帳・電話・名刺・遺品」
  这类 241 次重复的模板占 19,339 行，按"族"处理，不逐场景重复劳动。

改写规矩（第 70 批：438.0 序幕＋1.0／2.0，约 190 行）：

* **一段读通再落笔**：`俺は坊主の読経に耳を傾けながら。／旧友の写真を見つめていた，`
  → 「我听着和尚诵经。／望着旧友的遗照，」；`仕事もなく退屈に過ごす俺に。` →
  「没工作的日子过得无聊。」（不再译成"对没有工作整日无聊的我。"）
* **日语被动改主动**：`哲司の母親に声を掛けられた事に思わず驚いた` →
  「哲司的母亲叫住我／我一下子愣住了」；`静江に招かれ` → 「应静江之邀」。
* **去掉"让我吃惊的是…"这类翻译腔**：`驚いたのは唐突だったからではない` →
  「愣住不是因为来得突然」。
* **中文化比喻与收尾**：`我离开家渡海而去。` → 「我离家远渡重洋。」；
  `安らかに眠ってくれ` → 「安息吧」；`そう願う事しか出来ない` →
  「如今的我只能／这样祈愿，」（不再用"罢了"凑字数）。
* **标点跟着日文行**：日文中间行没有句读时，中文也不能加——分行本身就是停顿，
  加了逗号 `tm.py check` 立刻记一笔（本轮靠这条把违规从 8 降回 6）。

### 6.8 漏行补录：抽取器丢掉的短行（`tools/find_gap_runs.py` + `insert_pool_rows.py`）

玩家在告别式场景（1.0）发现洋子的台词前面冒出一句没翻译的「フフフ」。查 ROM 后确认：
那句**在母表里根本不存在**——`extract_pool.scan_pools` 只在"一批 ≥3 行且 ≥20 字"时才
输出，像 `」フフフ“““` 这种短行连同它的 16 字节槽位一起被跳过了，游戏继续显示日文。
`find_missing_runs.py` 也漏掉它，因为那个工具要求行里有平假名，而这条是纯片假名。

两个新工具的配合：

* `find_gap_runs.py`：只在**两条已导出行之间的小空档**（≤64 字节）里找 NUL 结尾的串，
  这是抽取器"跳过短行"留下的指纹；不含假名的行（纯数字/汉字）默认跳过——它们在中文里
  本来就读得通，或者根本是数据表。
* `insert_pool_rows.py`：逐条对**日文 ROM** 复验（槽位必须解码成候选文本并以 0x0000 结束）、
  拒绝与现有行重叠的候选、按**绝对偏移**写成 `pool` 行（`import_script` 就是这么回写的），
  然后给该条目的 pool 行重排连续 idx。重排**保持抽取器的扫描顺序**——`scene_index.py`
  靠这个顺序切存储块，按偏移重排会把场景切分打散（这一点是踩过的坑：第一版按偏移排序，
  剧情场景数从 625 掉到 390，已回退）。重排产生的 `(entry, idx)` 变化会同步改写
  `work/` 下的补丁文件，历史补丁仍然指向同一行。

还有一类**截断行**：33 行的 offset 被记录在句子的中间，游戏于是显示"日文头 + 中文尾"。
`--fix-truncated` 在候选文本正好以现有行文本结尾、且槽位放得下时，把该行挪回真正的起点
（实测 33 例的剩余空间与所需字节**完全相等**），并重新翻译。

本批结果：候选 593 条 → **插入 550 行 + 修复 33 行 + 跳过 10 条**（数据表碎片，
如 `・必`／`ー迷`，写了会破坏数据）。母表 101,795 → **102,345 行**，
`verify_rom.py` 回读 **102,345 / 102,345 一致**；`find_gap_runs` 复扫只剩那 10 条碎片。
补译表 `data/gap_translations.tsv` 随工具入库（67 条），重复出现的同一句沿用全表既有译法。

**踩坑记录**：母表表头**只列 7 个列名**，pool 行第 8 个值（`pool`）是匿名的，靠
`csv.DictReader(restkey='extra')` 读出来。我在重写母表时顺手把第 8 列命名为 `kind`，
结果导入器把 45k 个 pool 行当成表行处理、ROM 全乱——表头不能改。

### 6.9 语序优先：可以改分句，不能凭空加句读

玩家指出 438.0 的「这突然的讣告／就这么闯了进来。／就在今天早上，」虽然贴着日文，
中文却不是人话；要求改成「就在今天早上／这讣告就那么／突然地传了过来。」——
**按中文的语序走，不必遵守日文的分句**。这条对"…のは…だった""…を…と言う""动词殿后"
这类句子同样适用，本批照此重排了 2,221 行。

`tm.py check` 的标点判定因此改成**按句组（sentence group）比较**：

* 句组来自 `data/scene_lines.tsv` 的 `>`／`<` 连接标记——同一句被拆成几行显示时，
  逗号落在哪一行只是排版，不算错；
* **。 与 ， 视为同一类**：重排分句必然要在行尾互换这两个标记；
* **删**日文的停顿（`洋子君は。` → 「洋子…」）允许——中文不需要每个日文句读；
* **加**句读仍然算违规（中文不能自造停顿），当前 5 条是历史记账例外

## 八、第二类条目：无偏移表的「串池」（2025 补充，重要）

### 7.1 串池扫描的「后缀重复」陷阱（2025 收尾，务必保留这个过滤）

`scan_pools` 用 `re.search(r'[X6PCN]', txt)` 过滤位图假阳性，但**正文里也会出现数字和拉丁字母**
（`26分以上経っていますから`、`GNP`、`PS3`、`CD`…）。这类完整串会被误判为噪声而被拒，
而扫描器的重试步 `i = start + 2` 会**从下一个码重新起扫**，于是同一段字节里的**后缀**被当成新串收下：

```
e37 表行 idx 101  value 15386 + base 1952 = 17338   '」26分“““あ～。ダメダメ'
e37 pool 行       绝对偏移 17344 (= 17338 + 3 码)   '分“““あ～。ダメダメ'   ← 后缀重复
```

两行都会被翻译、都会被写回：**后写的短串把长串的尾巴覆盖掉**，成品 ROM 与主表不一致
（`verify_rom.py` 报 35 处 round-trip 差异）。

**处理**：

* `tools/fix_overlapping_pool_rows.py` —— 按「表行绝对偏移 = base + offset」算出表行槽位，
  删掉**整段落在表行槽位内且是其后缀**的 pool 行（实测正好 35 行，0 处无法判定）。
* `extract_pool.py` 的 `table_slots()` —— 现在扫描时会跳过起点落在表行槽位内的串段，
  重新提取不会再产生这类重复。

> 注意：**表行的 `offset` 列是偏移表里的原始值**，绝对偏移要 `+ base`（见 `entry_catalog.tsv`）；
> **pool 行的 `offset` 列才是绝对偏移**。比较两类行时必须先换算，否则会得出错误结论。

**最终规模**：`data/translation.tsv` = **96,477 行**（188 个表格式条目 + 291 个串池条目），
**96,477 / 96,477 全部有译文**，`tm.py check` 0 violations。
